# معماری و امنیت Solina

نسخهٔ سند: 0.1 (پیش‌نویس برای بازبینی) · وضعیت: طراحی

> مقادیر پارامترها (مثل Argon2id) پیش‌فرض‌های پیشنهادی هستند و در M2 با اندازه‌گیری روی دستگاه واقعی نهایی می‌شوند. هر تصمیم باز در بخش ۱۳ فهرست شده است.

---

## ۱. اصول

1. **Local-first:** برنامه بدون سرور و بدون اینترنت کامل کار می‌کند. همگام‌سازی افزونه است، نه پیش‌نیاز.
2. **Zero-Knowledge:** هر چیزی که از دستگاه خارج می‌شود (بکاپ، sync) فقط متن رمزشده است.
3. **یک کلید اصلی تصادفی (Vault Key):** رمز اصلی مستقیماً داده را رمز نمی‌کند. فقط Vault Key را «می‌پیچد» (wrap). پس تغییر رمز اصلی ارزان و ایمن است.
4. **فقط کتابخانهٔ معتبر:** Google Tink برای AEAD، و Argon2id از libsodium یا Bouncy Castle (انتخاب در M2 با توجه به مجوز و حجم). هیچ الگوریتم یا حالت اختصاصی.
5. **یک مکانیزم بازیابی:** عبارت ۲۴ کلمه‌ای BIP-39 (۲۵۶ بیت آنتروپی). «Recovery Key» جداگانه تعریف نمی‌شود.
6. **حداقل داده در متن ساده:** حتی نوع ورودی، عنوان و پوشه داخل بستهٔ رمزشده‌اند.

## ۲. سلسله‌مراتب کلید

```
Master Password ──Argon2id(salt, m,t,p)──► MasterKey (256-bit)
                                              │ HKDF("solina/wrap/pw")
                                              ▼
                                           KEK_pw ───────┐
                                                         ▼
Recovery Phrase (24 words, 256-bit) ─HKDF("solina/wrap/rec")─► KEK_rec ──┐
                                                         │               │
                                                         ▼               ▼
              Vault Key (VK, random 256-bit) ◄── wrap(VK, KEK_pw)   wrap(VK, KEK_rec)
                    │                                   (هر دو نسخه در هدر خزانه)
                    ├── wrap(ItemKey_i, VK)   ← هر ورودی یک کلید تصادفی
                    │        └─ AES-256-GCM(payload_i, ItemKey_i, AAD = id|rev|schema)
                    │
Android Keystore key (سخت‌افزاری در صورت امکان، نیازمند احراز هویت کاربر)
        └─ wrap(VK) → «نسخهٔ دستگاه» برای بازکردن با بیومتریک
```

نکات:

- **بیومتریک فقط میان‌بر است.** رمز اصلی همیشه معتبر می‌ماند. کلید Keystore با `setUserAuthenticationRequired` و (در صورت پشتیبانی) `setInvalidatedByBiometricEnrollment(true)` ساخته می‌شود تا با افزودن اثر انگشت جدید باطل شود.
- **تغییر رمز اصلی:** فقط `wrap(VK, KEK_pw)` جدید ساخته می‌شود. داده‌ها دست نمی‌خورند.
- **چرخش VK** (مثلاً پس از شک به نشت): ItemKeyها دوباره wrap می‌شوند. نیازی به رمزگذاری مجدد payload نیست.
- **پارامترهای Argon2id در هدر ذخیره می‌شوند** تا بعداً ارتقا یابند. پیش‌فرض: `m=64 MiB, t=3, p=4`. روی گوشی ضعیف تا حداقل `m=19 MiB, t=2, p=1` کاهش می‌یابد. هدف زمان باز شدن ≈ ۰٫۵ تا ۱ ثانیه که هنگام ساخت خزانه اندازه‌گیری و ثبت می‌شود.
- **Nonce:** ۹۶ بیت تصادفی برای هر رمزگذاری. چون هر ورودی کلید جداگانه دارد، سقف استفادهٔ GCM مشکلی ایجاد نمی‌کند.
- **جداسازی دامنه:** برچسب‌های HKDF برای هر کاربرد متفاوت‌اند. اگر روزی سرور ساخته شود، کلید احراز هویت سرور با برچسب جدا مشتق می‌شود و MasterKey هرگز به سرور نمی‌رسد.

## ۳. مدل داده (Room)

جدول `items` (فقط این‌ها متن ساده هستند):

| ستون | توضیح |
|---|---|
| `id` | UUID تصادفی |
| `rev` | شمارندهٔ نسخه برای sync |
| `updated_at` / `deleted_at` | زمان (برای tombstone) |
| `wrapped_item_key` | کلید ورودی، wrap شده با VK |
| `blob` | payload رمزشده |

داخل `blob`: نوع (login/card/identity/note/totp/…)، عنوان، فیلدها، URIها و پیوند به اپ‌ها، پوشه و برچسب‌ها، علاقه‌مندی، تاریخچه، فیلدهای سفارشی.

جدول‌های `vault_header` (نسخهٔ فرمت، سالت، پارامترهای KDF، دو VK پیچیده‌شده) و `item_history` (نسخه‌های قبلی رمزشده).

**جست‌وجو:** پس از بازشدن خزانه، ایندکس در حافظه ساخته می‌شود و با قفل شدن پاک می‌شود. برای چند هزار ورودی سریع است و هیچ ایندکس متن ساده‌ای روی دیسک نمی‌ماند.

## ۴. ماژول‌ها (Clean Architecture + MVVM)

```
:app                       ← اتصال DI، ناوبری، Application
:core:model                ← مدل‌های خالص Kotlin
:core:common               ← ابزارها، Result، dispatcherها
:core:crypto               ← KDF، AEAD، wrap/unwrap، BIP-39، تست‌وکتورها (بدون وابستگی به Android تا حد ممکن)
:core:security             ← VaultSession، قفل خودکار، Keystore، پاک‌سازی حافظه
:core:database             ← Room، DAOها
:core:designsystem         ← تم، کامپوننت‌ها (به DESIGN.md نگاه کنید)
:data:vault                ← Repository خزانه
:data:backup               ← ساخت/اعتبارسنجی/بازیابی فایل .solina
:data:sync                 ← آداپتورهای ذخیره‌سازی
:data:authenticator        ← TOTP/HOTP، ایمپورت‌ها
:feature:onboarding  :feature:vault  :feature:autofill  :feature:authenticator
:feature:generator   :feature:security-center  :feature:backup  :feature:settings
```

قواعد وابستگی: `feature → data → core`. ماژول `:core:crypto` هیچ‌چیز از لایهٔ بالاتر نمی‌شناسد. تنها ماژولی است که اجازهٔ import کردن کتابخانهٔ رمزنگاری دارد (با قاعدهٔ lint یا Gradle).

فناوری: Kotlin، Jetpack Compose + Material 3، Hilt، Navigation Compose، Coroutines/Flow، DataStore برای تنظیمات، Room، BiometricPrompt، CameraX برای QR. اسکنر QR با ZXing یا ML Kit (نسخهٔ bundled)، تا روی دستگاه بدون Google Play Services هم کار کند.

## ۵. جریان‌های بازکردن

1. **رمز اصلی:** KDF ← KEK_pw ← unwrap VK ← VaultSession در حافظه.
2. **بیومتریک:** `BiometricPrompt` با `CryptoObject` ← کلید Keystore ← unwrap نسخهٔ دستگاه VK.
3. **بازیابی:** ۲۴ کلمه ← KEK_rec ← unwrap VK ← اجبار به تعیین رمز اصلی جدید.

`VaultSession` پس از قفل (تایمر، خاموش شدن صفحه، رفتن به پس‌زمینه طبق تنظیم) VK و ایندکس را صفر می‌کند. محدودیت تلاش: backoff نمایی در رابط، و ثبت شمارش روی دستگاه. (در برابر حملهٔ آفلاین فایل، فقط Argon2id و قدرت رمز محافظ است. به کاربر در رابط صادقانه گفته می‌شود.)

## ۶. بکاپ (`.solina`)

ساختار فایل:

```
magic "SOLINA\0" | format_version | kdf_params | salt | wrapped_BK (با رمز بکاپ)
                  | wrapped_BK (با KEK_rec، اختیاری) | chunked AEAD payload
```

- کل هدر به‌عنوان AAD در AEAD احراز می‌شود. هر دست‌کاری (هدر یا داده) شناسایی می‌شود.
- **رمز مستقل بکاپ (اختیاری):** کلید بکاپ BK با Argon2id از رمز بکاپ مشتق می‌شود. بکاپ بدون نیاز به رمز اصلی باز می‌شود.
- **وضعیت واقعی پیاده‌سازی:** فرمت فعلی SLNB v1 فقط با رمز مستقل بکاپ باز می‌شود. عبارت ۲۴ کلمه‌ای، هدر خزانه را باز می‌کند و در نسخهٔ فعلی جایگزین رمز بکاپ نیست.
- **محدودیت شناخته‌شده:** بازیابی بکاپ روی گوشی جدید با عبارت بازیابی به‌تنهایی هنوز پیاده‌سازی نشده است؛ برای آن باید نسخهٔ جدید فرمت بکاپ، بسته‌بندی کلید بکاپ با KEK مشتق‌شده از عبارت بازیابی، و مسیر UI/تست مستقل اضافه شود. تا آن زمان نباید وعدهٔ بازیابی بکاپ با ۲۴ کلمه داده شود.
- **اعتبارسنجی پیش از بازیابی:** (۱) بررسی magic و نسخه، (۲) راستی‌آزمایی AEAD، (۳) بازیابی «خشک» در دیتابیس موقت، (۴) نمایش خلاصه (تعداد ورودی/کد)، (۵) جایگزینی اتمی. در هر مرحله خطا ← وضعیت قبلی دست‌نخورده.
- **ورودی‌های TOTP** جزو همان بکاپ‌اند. صادرکردن جداگانهٔ حساب‌های Authenticator هم ممکن است.
- هشدارها: «اگر رمز بکاپ و ۲۴ کلمه هر دو را گم کنید، داده قابل بازیابی نیست.»

## ۷. همگام‌سازی (M8، اختیاری)

- واحد همگام‌سازی: **رکورد رمزشدهٔ هر ورودی** با `(id, rev, deviceId, updatedAt)`.
- **آداپتورهای ذخیره‌سازی** با یک رابط یکسان: Google Drive (`appDataFolder`)، WebDAV/Nextcloud، پوشهٔ محلی (SAF)، و بعداً سرور شخصی.
- **تعارض:** در سطح ورودی. پیش‌فرض: نسخهٔ جدیدتر برنده است، و نسخهٔ بازنده در `item_history` ذخیره می‌شود تا هیچ‌چیز بی‌صدا گم نشود. تعارض فیلد-به-فیلد در نسخهٔ بعد.
- **حذف:** tombstone با نگهداری ۳۰ روزه.
- **خروج از حساب:** پاک‌سازی امن (صفر کردن کلیدها و حذف فایل‌های محلی) به‌صورت گزینهٔ جداگانه.
- متادیتای قابل‌مشاهده برای ذخیره‌ساز: id تصادفی، اندازه، زمان‌ها.

## ۸. Autofill

- `AutofillService` با تجزیهٔ `AssistStructure`.
- **تطبیق وب:** دامنهٔ ثبت‌شده (eTLD+1 با Public Suffix List). اگر دامنه تفاوت داشته باشد، پر کردن خودکار انجام نمی‌شود و فقط با تأیید صریح کاربر و هشدار پیشنهاد می‌شود.
- **تطبیق اپ:** `packageName` + اثر انگشت گواهی امضا. هنگام اولین ذخیره ثبت و در دفعات بعد مقایسه می‌شود. برای ارتباط رسمی اپ-وب از Digital Asset Links هم استفاده می‌شود.
- مرورگرها: فقط مرورگرهای لیست مورد اعتماد که `webDomain` معتبر می‌دهند (یا حالت سازگاری با هشدار).
- Dataset احراز‌شده: برای هر پر شدن باید خزانه باز باشد. در غیر این صورت BiometricPrompt یا رمز اصلی.
- Inline suggestions (Android 11+) با ظاهر هماهنگ با تم.
- **بعداً (v1.1):** Credential Manager و Passkey از طریق `CredentialProviderService` (Android 14+).

## ۹. Authenticator

- RFC 4226 (HOTP) و RFC 6238 (TOTP)، الگوریتم‌های SHA-1/256/512، ۶ تا ۸ رقم، دورهٔ ۳۰ یا ۶۰ ثانیه. نوع Steam اختیاری.
- ورودی: QR، `otpauth://`، و دستی.
- ایمپورت: Aegis (JSON ساده و رمزشده)، `otpauth-migration://` (Google Authenticator)، و لینک `otpauth` دسته‌ای.
- راز TOTP همانند هر ورودی دیگر رمز می‌شود و می‌تواند به یک ورودی Login وصل باشد.
- نمایش: کدها همیشه با ارقام لاتین و جهت LTR. در ۵ ثانیهٔ آخر پیش‌نمایش کد بعدی.
- برای دقت زمانی به ساعت سیستم تکیه می‌شود. در صورت اختلاف زیاد با زمان شبکه (اگر کاربر اجازه دهد) هشدار می‌دهد.

## ۱۰. ورود با حساب خارجی

- **Google (OAuth/OIDC):** برای دسترسی به `drive.appdata` جهت بکاپ و sync. هویت کاربر روی سرور شخصی (در آینده). هرگز کلید خزانه را باز نمی‌کند.
- **GitHub (OAuth):** بدون سرور کاربرد مهمی ندارد، پس به بعد از ۱٫۰ موکول می‌شود (هویت روی سرور شخصی).
- قطع اتصال حساب هیچ‌وقت داده را حذف نمی‌کند. چند حساب هم‌زمان ممکن است.
- هیچ رمز، کلید یا متن ساده‌ای به این سرویس‌ها نمی‌رود.
- دستگاه بدون Google Play Services (مثل F-Droid): همهٔ قابلیت‌های محلی، WebDAV و پوشهٔ محلی کار می‌کنند.

## ۱۱. مدل تهدید (خلاصه)

| تهدید | کاهش ریسک |
|---|---|
| گوشی قفل‌شدهٔ گمشده یا دزدیده‌شده | Argon2id، کلید Keystore، قفل خودکار، رمزگذاری کامل payload |
| اپ مخرب برای خواندن کلیپ‌بورد یا صفحه | `FLAG_SECURE`، علامت‌گذاری کلیپ حساس (`EXTRA_IS_SENSITIVE`)، پاک‌سازی خودکار، نبود لاگ حساس |
| فیشینگ از طریق Autofill | تطبیق دامنه/امضای اپ، بدون پر کردن در عدم تطابق |
| سرقت فایل بکاپ | AEAD با کلید مستقل از Argon2id، رمز مستقل، احراز هدر |
| نفوذ به سرویس ابری یا سرور | فقط متن رمزشده، کلیدها هرگز نمی‌روند |
| زنجیرهٔ تأمین (وابستگی مخرب) | قفل‌کردن نسخه‌ها، SBOM، بازبینی وابستگی، امضای انتشار، هدف ساخت قابل بازتولید |
| رمز اصلی ضعیف | سنجش قدرت، پیشنهاد عبارت‌عبور، هشدار صادقانه دربارهٔ حملهٔ آفلاین |
| فراموشی رمز و عبارت بازیابی | غیرقابل بازیابی توسط طراحی. هشدار روشن و تأیید ذخیره‌سازی در onboarding |
| دستگاه root/آلوده در سطح کرنل | **خارج از دامنه** (مستند می‌شود) |

## ۱۲. تست و کیفیت

- **تست‌وکتور رسمی:** RFC 4226 پیوست D، RFC 6238 پیوست B، RFC 9106 برای Argon2id، بردارهای BIP-39.
- تست واحد برای همهٔ ماژول‌ها، و تست یکپارچهٔ رمزگذاری با Room.
- **Fuzz** پارسر `.solina` و پارسرهای ایمپورت (Aegis، otpauth، CSV).
- تست بازیابی کامل بکاپ و انتقال به دستگاه دوم. تست‌های دستی و خودکار Autofill (Chrome، Firefox و چند اپ نمونه).
- تست آفلاین و تعارض در sync با دو شبیه‌ساز.
- تحلیل ایستا: ktlint، detekt، Android Lint، اسکن وابستگی (OSV-Scanner یا مشابه).
- نگاشت به **OWASP MASVS v2** (STORAGE, CRYPTO, AUTH, NETWORK, PLATFORM, CODE, RESILIENCE, PRIVACY) و یک چک‌لیست در مخزن.
- CI با GitHub Actions: build، lint، تست، اسکن وابستگی در هر PR.
- انتشار نهایی فقط پس از بازبینی امنیتی مستقل.
