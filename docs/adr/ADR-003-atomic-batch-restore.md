# ADR-003: اتمیک‌بودن ایمپورت و بازیابی دسته‌ای

- وضعیت: پذیرفته‌شده برای پیاده‌سازی اولیه؛ تأیید نهایی منوط به تست instrumentation روی Room است.
- تاریخ: 2026-11-13
- شاخه: `preview/rebuild-phase-01`

## زمینه

`VaultRepository.importItems` قبلاً هر رکورد را جداگانه با `ItemStore.save` ذخیره می‌کرد. اگر ذخیرهٔ رکورد میانی شکست می‌خورد، رکوردهای قبلی باقی می‌ماندند؛ در حالی که عملیات بازیابی باید یا کامل انجام شود یا هیچ تغییری ندهد.

## تصمیم

1. قرارداد `ItemStore.saveAll` تضمین می‌کند که کل batch به‌صورت اتمیک ذخیره شود.
2. `VaultRepository` ابتدا ورودی‌ها را رمز می‌کند و ردیف‌های ذخیره‌شده را در حافظهٔ موقت می‌سازد؛ تا پایان این مرحله هیچ ردیفی نوشته نمی‌شود.
3. `RoomItemStore.saveAll` همهٔ upsertها را داخل یک `RoomDatabase.withTransaction` انجام می‌دهد.
4. وضعیت `StateFlow` و شمارندهٔ تغییرات فقط پس از موفقیت ذخیره‌سازی منتشر می‌شوند.
5. رفتار قبلی حفظ می‌شود: موارد تکراری skip می‌شوند و تاریخ‌های اصلی ورودی‌ها حفظ می‌شوند.

## پیامدها و محدودیت‌ها

- خطای رمزگذاری پیش از ذخیره‌سازی باعث هیچ تغییر پایدار نمی‌شود.
- خطای داخل تراکنش Room باید تمام upsertهای همان batch را rollback کند.
- تست واحد با FakeStore رفتار Repository را هنگام failure بررسی می‌کند، اما جای تست instrumentation روی SQLite/Room واقعی را نمی‌گیرد.
- این تصمیم هنوز به‌تنهایی M6 را کامل نمی‌کند؛ تست دستگاه جدید، parser fuzzing و تست‌های واقعی Room همچنان لازم‌اند.
